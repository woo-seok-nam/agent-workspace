# 자연어 → 계획 → 실행 → 답변 (v0.32.0)

현재 인터페이스는 터미널 CLI입니다. 새 웹/데스크톱 화면을 추가한 것은 아닙니다. 기존 .env의 학교 AI 설정을 사용합니다.

## 1. 자연어로 계획 만들기

프로젝트 agent-runtime 폴더에서:

```powershell
npm.cmd run task -- --request "AI 에이전트와 워크플로우의 차이를 초보자가 이해하도록 예시와 함께 설명해줘. 웹 검색 없이 답변해줘."
```

실제 AI를 호출해 JSON 계획을 생성·검증하고 Markdown 계획을 터미널과 `.local/tasks/ID/plan.md`에 표시합니다. 이 단계에서는 계획을 실행하지 않습니다. 기계가 실행할 원본은 같은 폴더의 record.json입니다. plan.md만 편집해도 실행 내용은 바뀌지 않습니다.

요청만으로 가능한 작성 작업은 최초 요청 원문을 user_request 입력으로 자동 전달합니다. 요청에 없는 실제 기획안·인터뷰 원문·파일 내용을 만들어 채우지는 않습니다. 추가 필수 입력이 있으면 inputs.json에 빈 항목을 만들어 안내합니다. 자료는 해당 항목 값에 텍스트로 입력하거나 --input-files files.json으로 TXT/MD 매핑을 전달할 수 있습니다. 같은 포트를 두 방식으로 중복 입력하지 마세요. user_request는 직접 지정하거나 덮어쓸 수 없습니다.

모호하거나 충돌하는 요청은 질문만 표시합니다. 표시된 generate --resume ... --answer ... 명령으로 답한 뒤 새 record.json을 task --run에 지정할 수 있습니다.

## 2. 계획 확인 후 실행

계획 생성 마지막에 실제 경로가 포함된 실행 명령이 표시됩니다. 복사해서 사용하세요. 아래 ID는 예시 자리 표시입니다.

```powershell
npm.cmd run task -- --run .local/tasks/ID/record.json --inputs .local/tasks/ID/inputs.json
```

추가 입력이 없다면 --inputs를 생략할 수 있습니다. 입력 내용이 비어 있는 필수 항목은 누락으로 표시합니다. --check를 붙이면 API 없이 준비 상태만 검사합니다. 준비 검사 통과 후에만 실제 AI 작업을 수행합니다. 저장된 계획을 사용하며 실행 시 계획을 다시 생성하지 않습니다.

최종 검토를 통과하면 답변을 터미널에 표시하고 `.local/tasks/ID/runs/실행ID/answer.md`로 저장합니다. 실행마다 새 폴더이므로 이전 답변은 유지합니다. 실행 기록은 execution.json, 입력 파일 출처는 sources.json에 저장합니다. 일반 generate 경로에서 나온 task 모드 기록이라면 그 기록 옆 runs 폴더를 사용합니다.

검토가 계속 수정 필요이면 최대2회 수정 후 needs_review로 멈추고 draft.md/review.md를 저장합니다. 이때 answer.md는 만들지 않습니다. 중단된 실행은 기존 execute --resume execution.json 기능을 사용할 수 있습니다. Ctrl+C와 5분 실행 제한을 적용하며 단계별 기록을 저장합니다.

## 지원 범위

- 순차 텍스트 작업과 AI 최종 검토, Markdown 계획과 답변
- 기존 자료 입력·출처 표시·보정·재개 기능 활용
- 웹 검색 및 외부 도구 실행은 아직 연결되지 않았습니다. 필요 도구나 사람 작업이 선언된 계획은 이유를 표시하고 차단합니다.
- PDF 등 비텍스트 산출물은 현재 실행기에서 지원하지 않습니다.
- 입력 길이·문맥 제한은 기존 생성기/실행기 제한을 따릅니다. 입력을 조용히 잘라 보내지 않습니다.
- 자체 모델 지식에 기반한 답변의 정확성과 최신성을 보장하지 않습니다.

로컬 고정 응답으로 전체 흐름과 오류 분기를 테스트했습니다. 학교 AI를 통한 실제 생성·실행 품질은 사용자 환경에서 위 명령으로 확인해야 합니다.
